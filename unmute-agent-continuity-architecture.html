Unmute Agent should understand work, not expose session mechanics.

Continue naturally.
Preserve identity precisely.

The user says what they want. Unmute decides whether that means resume, fork, synthesis, or fresh work—then uses the provider’s real operation, never a disguised substitute.

source: 552578f1… → resume means 552578f1… remains the session

A task-card ID may be new because it belongs to Unmute’s UI. The provider session/thread ID must obey the chosen operation: unchanged for resume, provider-created child for fork, new only for synthesis or fresh work.

What the branch does today

The foundations are strong: structured chat, exact transcript lookup, persistent Agent identity, and provider-native transports already exist. The orchestration verb is the broken seam.

Already correct

Owned task, existing card

Wake the card, resume its recorded session, then send the user’s exact follow-up. No synthetic prompt is added when the user only asks to reopen it.

Semantic mismatch

On-disk session without a card

The only MCP verb is called session_resume, but planResume() changes the operation to fork and defaults the prompt to “Continue from where we left off.”

Already available

Multi-session background

task_create.context can carry up to 24k characters of summarized background into a fresh session. This is the correct basic mechanism for synthesis.

Provider hole

Codex fork from Unmute Agent

The task dispatcher routes Codex to dispatchCodexCli(), which currently starts a new app-server thread and does not consume forkFromSessionId. History is therefore not forked.

These operations are structured and headless. They do not require restoring the old terminal/PTY interface.

Required changes, by seam

Fix identity semantics first. Then make natural multi-session retrieval reliable. This order prevents a smarter planner from invoking the wrong primitive more often.

agent/constitution.ts

Replace “always call session_resume” with an explicit intent policy: exact continuation → resume; alternate branch → fork; multiple/cross-provider/oversized sources → synthesize; no match → fresh. Never invent “continue” as a user turn.

Prompt
agent/capabilities/sessions.ts

Expose separate, non-overlapping session_resume and session_fork tools. Their schemas must make the source ID exact and must report both source and resulting provider identity.

MCP
agent/sessions/resume.ts

Delete the resume→fork reinterpretation and REOPEN_INTENT. Resume planning may wake an existing card or attach the exact on-disk session; it must never mint a provider session.

Planner
task-manager.ts

Add explicit provider-neutral operations such as attachExistingSession() and forkSession(). Keep Unmute task-card IDs separate from provider IDs. Do not overload dispatch(), whose meaning should remain “start new work.”

Runtime
codex/hub.ts

Add forkThread() over official thread/fork; hydrate returned history and register the child mapping exactly as startThread()/resumeThread() do.

Codex
claude/task-session.ts

Keep the existing native structured fork and resume flags. Use the source ID only for resume; for a fork, accept the child identity returned by Claude and persist forkedFrom.

Claude
remote/init.ts + runtime host

Remove the duplicated fork-on-resume adapters. Both in-process and daemon-hosted paths should call one shared continuation service so they cannot drift.

Wiring
agent/capabilities/handoff.ts

Extend synthesis with validated sourceSessions, optional working directory, and structured artifact references. Keep intent verbatim and context as background; store provenance outside the prompt.

Synthesis
session retrieval

Add a cheap deterministic session catalog or on-demand projection for provider, cwd, timestamps, user turns, artifacts, and summaries. Use raw transcripts as source of truth; do not return to periodic model-generated sweeps.

Recall
task metadata + UI

Persist continuationMode, source IDs, confidence, and artifact references. Keep it visually quiet (“Continued from earlier work”) but expandable for trust and debugging.

Provenance
evals + contract tests

Test natural utterances, ambiguous matches, exact ID invariants, absence of synthetic prompts, provider parity, multi-source bounds, missing cwd, and active-source behavior.

Proof

A cleaner MCP contract

The model selects the semantic operation. Runtime code enforces its identity invariant. Neither layer is allowed to silently substitute another operation.

{
  "session_resume": {
    "sessionId": "exact provider ID",
    "intent": "optional exact next user action"
  },
  "session_fork": {
    "sessionId": "exact source provider ID",
    "intent": "optional exact next user action"
  },
  "task_create": {
    "intent": "the user's current request",
    "context": "bounded synthesis, not commands",
    "sourceSessions": [
      { "sessionId": "…", "provider": "claude" },
      { "sessionId": "…", "provider": "codex" }
    ],
    "artifacts": [
      { "kind": "url", "value": "…" },
      { "kind": "file", "value": "/…" }
    ],
    "kind": "session",
    "provider": "optional explicit target",
    "cwd": "optional validated directory"
  }
}

Hard invariants

Resume never forks.
Same provider ID before and after.
Fork never guesses.
The exact source ID is passed; the provider returns the child ID.
Reopen never speaks.
An omitted intent means zero submitted user turns.
Synthesis never impersonates resume.
It is a new session, labeled as a continuation from selected sources.
Artifacts are data, not prose.
Links, file paths, sheet IDs, and identifiers survive summary compression.

What proves it works

Focused contract checks are enough. This does not require broad, unrelated regression testing.

✓
Exact Claude resume

The structured launch contains --resume SOURCE_ID, no fork flag, and the task stores SOURCE_ID.

✓
Exact Codex resume

The hub sends thread/resume with SOURCE_ID and never calls thread/start.

✓
Native provider forks

Claude uses --fork-session; Codex uses thread/fork; each records the returned child ID.

✓
No ghost prompt

Reopening without an intent adds no “continue,” “resume,” or hidden follow-up turn.

✓
Multi-source continuity

A fresh session receives bounded relevant context plus lossless artifact references and source provenance.

✓
Natural selection

High-confidence matching acts automatically; conflicting consequential targets produce one concise clarification.

✓
Active work

If the exact session already has a live card, the new action lands there—no duplicate card or provider process.

✓
Provider honesty

Cross-provider continuation is described as synthesis, never as moving or resuming the original thread.

The correct abstraction is one user verb—continue—backed by four precise runtime operations that never masquerade as one another.
