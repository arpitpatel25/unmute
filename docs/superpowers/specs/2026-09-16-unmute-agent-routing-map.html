What the Unmute Agent is

Not an ordinary task session. It is a locked-down Claude or Codex session, wrapped in pieces Unmute owns: a chat card, a background process that holds the conversation, a rulebook, a private tool server, and direct read access to your history. How a workflow like “resume” is set up

There is no step-by-step orchestration in code. A workflow is prose the model reads, a tool it may call, and a guard in code that blocks the irreversible mistake. The model runs the whole thing in one loop, choosing which tools to call and in what order.

What “resume” actually is

  • A few of the 54 rule paragraphs: look before deciding, decide what the sentence wants, break ties by what a session touched, check Unmute owns it, reply with a one-line receipt.
  • A tool description for session_resume, which the model reads alongside the rules.
  • A guard in code (agent/sessions/resume.ts): never turn a resume into a fork, never match a truncated id, never attach to a session running in your terminal, wake the existing card instead of making a second one.

Every other workflow — relay, fork, hand off, remember, find a dictation — is built the same way. The rules read like a procedure, but nothing executes them as one: the model interprets them.

Is that less predictable? Yes.

On 16 September, almost the same build request went three different ways:

11:42resumed the card, passed the words only (old rules, Claude) 16:07resumed the card again (old rules, Claude) 16:45read the right session, then made a new task (new rules, Codex)

Why: 54 rules compete and some contradict each other; Claude and Codex read the same prose differently; a long chat history nudges the model to repeat what it did before.

It was deliberate. A 7 September design rule says never write procedure into the rules and guard only the irreversible act, to keep the Agent flexible for open-ended requests. The cost is that which route it takes is not reliable.

A proposed middle ground

Keep the model free where judgement helps — finding sessions, reading transcripts, writing the message — and make the routing decision structured:

  • The Agent first states its decision as data: which route, which destination card, which source sessions.
  • Code checks that decision and carries it out, so the same decision always does the same thing.
  • A fixed set of test sentences checks that each still produces its expected route whenever the rules change.

Not built. It reverses the 7 September rule, so it needs a decision first.

What the Agent reads on every turn

Two layers. The rules are loaded once when the Agent’s process starts; everything else is rebuilt for each thing you say. Nothing is trimmed or selected — the whole of it goes every time. Widths below are to scale by character count.

Where it looks, and in what order

There is no pocket-first cascade. The rules make the Agent read three sources together, before it has decided what kind of request this is — then it goes deeper only where the request points.

When several sessions match

Rule: When more than one could be it, look at what was actually done.

  1. What each candidate touched — files, links, notes, documents — read at its offset. A session that was only talk touched nothing.
  2. returns on the session row: how many times you left and came back. Coming back means you accepted it.
  3. Never how a session describes itself: “done” can open with “I could not complete this”. Recency points the wrong way — the failed attempt is usually the newer one.
  4. Only main conversations count. Sub-agent sessions are never sources; sessions opened by software (briefing:true) are never what you mean by your work.

Exceptions to the sweep

Where the rules pull against the always-read-three rule.

Questions about memory

“What’s Rishi’s address?” is answered from memory alone. If it is not there: say so, offer to look, and stop — do not search the disk.

agreement with the sweep, which still demands the index read first

A read already in this conversation

If the last turn found the session, note or task, answer from that instead of sweeping again. A read from ~15 turns ago counts as stale.

a concrete threshold

Sessions Unmute did not start

Anything with a cwd outside ~/.unmute/remote/ is read, never resumed (3,222 of 4,077 on one machine). Its knowledge is carried into a new task instead.
